# Slipstream Live

🌐 [English](README.md) | 日本語

📘 **[取扱説明書](https://tail4126.github.io/SlipstreamLive/manual.ja.html)** — インストールから設定項目、困ったときの対処まで、画面写真つきでまとめています。

> **ライブ配信は必ず数秒遅れている。その遅れを、見ている間ずっと自動で詰め続けます。**

**Slipstream Live** は、**YouTube Live**・**Twitch**・**ツイキャス（TwitCasting）** 向けのブラウザ拡張機能です。

ブラウザがどれだけ先まで映像を読み込めているか（バッファ残量）を監視し、再生速度をほんの少しだけ上げ下げすることで、**映像を止めずに**配信の「今」へ近づけ続けます。

インストールすれば、あとは何もしなくて大丈夫です。

---

## 🤔 何が便利なの？

ライブ配信で見えている映像は、配信者が実際にしゃべっている瞬間より必ず数秒遅れています。
この遅れは回線が乱れるたびに増えていき、放っておいても縮みません。

手動で 1.25 倍速にすれば追いつけますが、そうすると今度は自分でバッファ残量を見張り、なくなる前に速度を戻さないと、映像が「くるくる」で止まってしまいます。

Slipstream Live は、その見張りを 1 秒間に約 50 回、自動で行います。

| こんなとき | Slipstream Live の動き |
| :--- | :--- |
| 遅れているが、先の映像は十分読み込めている | 少しだけ加速（1.25x）して追いつく |
| 読み込み済みの映像がほぼ尽きた | 0.15x まで落とし音量も下げて、完全停止を回避 |
| 問題なし | 何もしない（通常の 1.00x） |

## ✨ 主な機能

* 🌐 **3 サイト対応** — YouTube / Twitch / ツイキャス。それぞれに合わせた既定値を用意。
* 🚀 **自動で追いつく** — 「安全に加速できる」と判断できたときだけ加速します。
* 🧠 **配信ごとに自動学習** — 適切なバッファの余裕を自分で計算するので、秒数を手で当てる必要がありません。
* 🛡️ **停止回避の最減速** — 最後の手段として 0.15x まで落とし、映像を止めずにバッファを回復させます。
* 🔊 **音量の自動ダッキング** — 極端なスロー再生で歪んだ音声を、一時的に絞って和らげます。
* 📊 **プレイヤー上のバッジ表示** — 再生速度・遅延秒数・バッファ残量（既定はオフ）。
* 🌍 **9 言語の UI** — 日本語・English・한국어・Deutsch・Español・Français・Português (BR)・简体中文・繁體中文。
* 🔒 **通信なし・追跡なし** — 詳しくは [PRIVACY.md](PRIVACY.md) へ。

## 🔄 3 つの制御モード

| モード | 優先度 | バッジ色 | 速度 | 発動条件 |
| :--- | :---: | :---: | :---: | :--- |
| **Floor（最減速）** | 最高 | 青 (`#83c1ff`) | **0.15x**（固定） | バッファ枯渇の直前。緊急ブレーキ＋音量ダッキング。 |
| **Speedup（加速）** | 低 | 赤 (`#ff8983`) | 1.25x | バッファに十分な余裕がある。最先端へ追いつく。 |
| **Normal（通常）** | — | 白 (`#eee`) | 1.00x | 何もしない。 |

優先度の高いモードが常に優先されます。
Floor の 0.15x は安全装置なので、意図的に変更できないようにしてあります。

各しきい値には現在のモードへ留まる向きにヒステリシスが掛かっており、境界ちょうどで倍率と音量が細かく往復しないようになっています。
幅は「バッファ閾値を自動調整する」の段階に連動し、**オフ・標準では 0.1 秒、積極的では 0.05 秒**です。

**制御しないもの:** アーカイブ（VOD）・クリップ・広告再生中には一切手を出しません。
ライブ再生中のみが対象です。
ツイキャスの**低遅延配信**も対象外です。
低遅延モードは WebRTC で映像が届くため、測定できる先読みバッファがなく、再生速度を変えても仕様上無視されます。
そもそもほぼリアルタイムなので、詰めるべき遅れがありません。

**YouTube とツイキャスでは**、あなたがプレイヤーのメニューで 1.00x 以外の速度を選んだ場合、Slipstream Live は制御を譲って手を引きます。
（Twitch には速度変更メニューがないため常に Slipstream Live が制御し、あわせて Twitch 自身の追いつき機能が競合しないよう抑え込みます。）

## ⚙️ 設定項目

### サイト別設定

| 設定項目 | 範囲 | YouTube | Twitch | TwitCasting | 説明 |
| :--- | :---: | :---: | :---: | :---: | :--- |
| **遅延時に加速する** | ON / OFF | ON | ON | ON | 追いつき機能のスイッチ。 |
| **遅延時の再生速度** | 1.05x〜4.00x | 1.25x | 1.25x | 1.25x | 加速時の倍率（0.05 刻み）。大きいほど速く追いつけますが、バッファ消費も増えます。 |
| **バッファ閾値を自動調整する** | オフ / 標準 / 積極的 | 標準 | 標準 | 標準 | 加速して安全かどうかを Slipstream Live に判断させます。**推奨。** |
| **加速するバッファ閾値** | 0.1〜100.0s | 10.0s | 10.0s | 10.0s | 自動調整が **オフのときだけ**使われます。この秒数まで読み込めていたら加速。 |
| **バッファ枯渇時に最低速度する** | ON / OFF | ON | ON | ON | 0.15x の緊急ブレーキのスイッチ。 |
| **最低速度する閾値** | 0.0〜10.0s | 0.80s *(FF: 1.00s)* | 2.00s *(FF: 0.50s)* | 0.10s *(FF: 0.30s)* | バッファ残量がこれを下回ると 0.15x へ。 |
| **最低速度中は音量を下げる** | ON / OFF | ON | ON | ON | 0.15x の間だけ音量を絞ります。 |
| **最低速度中の音量** | 0〜100% | 30% | 30% | 30% | **今の音量に対する**割合（5% 刻み）。100 で変化なし、0 で無音。 |

*FF = Firefox での既定値。Firefox はバッファ残量の報告のされ方が異なるため、専用の値を持ちます。
YouTube とツイキャスでは大きめ、Twitch では逆に小さめと、方向は一律ではありません。*

> **Twitch の閾値だけ大きいのはなぜ？** Twitch では映像データの到着が 10 秒ほど途切れることがあります。
> 実際に止まる前に反応できるよう、既定値を大きめにしています。

#### 「バッファ閾値を自動調整する」の 3 段階

| 段階 | 谷を貯める窓 | 安全余裕係数 | 下限への上乗せ | ヒステリシス | 性格 |
| :--- | :---: | :---: | :---: | :---: | :--- |
| **オフ** | — | — | — | 0.1s | 自動調整せず「加速するバッファ閾値」をそのまま使います。 |
| **標準** | 30s | 5 | 0.3s | 0.1s | 長い窓と大きな係数で慎重に判断します。既定値。 |
| **積極的** | 5s | 3 | 0.1s | 0.05s | 短い窓で直近の余裕へ素早く反応し、遅れをより詰めます。 |

### 全サイト共通設定

| 設定項目 | 既定値 | 説明 |
| :--- | :---: | :--- |
| **再生速度を変更する** | ON | マスタースイッチ。オフにすると Slipstream Live は完全に停止します。 |
| **再生速度倍率を表示** | OFF | 現在の再生速度をプレイヤー内に表示。 |
| **遅延秒数を表示** | OFF | 最先端からの遅れを表示。 |
| **バッファ残量を表示** | OFF | 何秒先まで読み込めているかを表示。 |

## 💡 動作の仕組み

### かんたんな説明

Slipstream Live は 20 ミリ秒ごとに**バッファ残量**（何秒先まで映像を読み込めているか）を測り、その値から 3 つのモードのどれかを選びます。

難しいのは「いつ加速して安全か」の判断です。
バッファ残量は一定ではありません。
映像は「セグメント」という数秒単位の塊で届くため、塊が届いた瞬間にドンと増え、再生とともにすーっと減っていきます。
グラフにすると**のこぎり波**の形になります。

もし適当な瞬間に測って、たまたま**山（ピーク）**を見てしまうと、「余裕たっぷり」と誤解して加速し、直後の**谷**でバッファを使い切って映像が止まります。
そこで Slipstream Live は、1 回の測定値を信じる代わりに、**谷がどこにあるか**を統計的に推定します。

### 数式による詳細（読み飛ばし可）

<details>
<summary>セグメント長を知らずに「谷」を求める方法</summary>

のこぎり波をでたらめなタイミングで測ると、その値は区間 `[trough, trough + S]`（`S` はセグメント長）の一様分布に従います。
一様分布には次の性質があります。

$$avg = trough + \frac{S}{2}, \qquad sd = \frac{S}{2\sqrt{3}}$$

2 番目の式を `S` について解いて 1 番目へ代入すると、未知数 `S` がきれいに消えます。

$$trough = avg - \sqrt{3} \times sd$$

つまり短時間の**平均**と**標準偏差**さえ測れば、配信のセグメント長を一切知らなくても谷の位置がわかります。
測定に使う短期窓は配信ごとに自動調整され（おおむねセグメント長、1〜30 秒に制限）、標本が 8 個以上かつ窓の半分以上が埋まるまでは推定を保留します。
1 周期に満たない観測から「危険側に外れた楽観的な答え」が出るのを防ぐためです。

さらに、推定を歪める 2 つの要因を補正しています。

* **既知入力の補償** — Slipstream Live 自身が 1.25 倍で再生している間、バッファは回線とは無関係な理由で減ります。
  そこで 1.0 倍からの超過消費 `D(t) = ∫(rate − 1)dt` を累積し、標本を補償座標 `health + D(t)` で保持することで、自分の操作が自分の観測を汚さないようにしています。
  これが無いと「加速する → 余裕が枯れる → 通常速度へ戻る → また加速する」という自励振動が起きます。
* **定常性の判定** — 起動直後やスタール復帰直後はバッファの水準そのものが速く動くため、標準偏差がのこぎり波の振幅ではなく水準の移動量を測ってしまいます。
  補償座標の傾きは式を展開すると「取り込み速度 − 1」に等しくなるため、回線の状態だけを取り出せます。
  この傾きが 0.9 秒/秒 を超えている間は谷を推定せず、谷の履歴ごと破棄します（汚れた谷を 1 つ混ぜるだけで、以降は窓の長さのあいだ統計が壊れるためです）。
  なお傾きは 1 秒ぶんの履歴が貯まってから求めます。
  もっと短い間隔で求めると、平均のわずかな揺れが増幅されて「常に定常でない」と判定されてしまいます。

統計に使う標本は等間隔のタイマー駆動の tick からのみ採ります。
制御ループは `timeupdate` / `progress` / `waiting` でも走りますが、`waiting` は「バッファが尽きた瞬間」に集中して発火するため、これを混ぜると分布が谷側へ偏り、一様分布の前提が崩れます。
イベント駆動の tick では `D(t)` の積算だけを行います。
同様に、一時停止中・シーク中・データ待ち（`readyState < 3`）の区間はバッファが倍率どおりには減らないため、`D(t)` の積算を見送ります。

推定された谷は長期窓（標準 30 秒 / 積極的 5 秒）に貯められ、安全係数 `K`（標準 5 / 積極的 3）で差し引いて実効的な余裕バッファ量を求めます。

$$room = troughAvg - K \times troughSd$$

谷の履歴が 1 秒ぶん貯まるまで `room` は `NaN` のままです（標本が 1 個だと標準偏差が 0 になり、安全余裕がまったく引かれずに素通りしてしまうためです）。
この `room` が「確保したいバッファ量」（最低速度する閾値＋段階ごとの上乗せ量。
機能がオフなら上乗せ量のみ）を上回っている間だけ加速します。
`K` が大きいため、谷が**安定して同じ高さ**でないと余裕が生まれず、回線が不安定なときは自然と加速が抑制されます。
またデータが足りない間 `room` は `NaN` となり、どんな比較も false になるため、「わからないときは何もしない」が自動的に成立します。

これらすべての上に、ひとつだけ近道があります。
残量が 20 秒（「最低速度する閾値」を大きくしている場合は「確保したいバッファ量＋10 秒」のうち高いほう）を超えている間は、谷の推定を待たずに加速します。
残量が 15 秒を下回ると、従来どおりの統計による判定へ戻ります。
これは手動でシークした直後に効きます。
バッファを埋め直している間は取り込み速度が 1.0 を大きく上回るため、定常性の判定は正しく「谷を記録しない」と振る舞いますが、この近道が無いと、すでに 1 分ぶん読み込めているのに 1.00 倍のまま止まってしまうためです。
近道が働くのは自動調整が「標準」「積極的」のときだけで、「オフ」のときは設定した手動閾値がそのまま使われます。

</details>

バッジの再描画は毎秒 10 回までに抑えられ、統計もすべて平滑化されているため、速度が目に見えてばたつくことはありません。

制御対象が見つからない間は 1 秒周期の探索モードへ落ち、5 秒経っても確定しなければタイマーを完全に止めてメディアイベント待ちへ移ります。
タブが表に戻った瞬間にも一度だけ実行されます。

## ❓ 困ったときは

**まったく加速しない**
自動調整はわざと慎重に作ってあります。回線が不安定だと「加速は危険」と判断するためです。まず **「バッファ閾値を自動調整する」を「積極的」** に変えてみてください。それでも足りなければ **「オフ」** にして **「加速するバッファ閾値」** を手動で設定します（15〜20 秒あたりから始めて、様子を見ながら下げていくのがおすすめです）。

**シーク直後、バッファは十分あるのに 1.00x のまま**
1.1.0 以降であることを確認してください。このバージョンから、バッファ残量が 20 秒を超えていれば谷の統計を待たずに加速します。シーク直後は読み込みが一気に進むため、統計がしばらく使えない状態になるためです。

**最低速度（0.15x）に入る頻度が高い**
手動閾値を大きめにするか、**「遅延時の再生速度」** を下げてバッファの消費を緩やかにしてください。それでも頻発するなら **「最低速度する閾値」** を下げれば発動は遅くなりますが、実際に映像が止まるリスクは上がります。

**何も起こらない**
**「再生速度を変更する」** がオンになっているか、VOD やクリップではなく **ライブ** 配信を見ているか、プレイヤーのメニューで再生速度を手動変更していないかを確認してください。

**ツイキャスで何も起こらない**
低遅延配信を見ていないか確認してください。低遅延モードは WebRTC で配信されるため、Slipstream Live の制御対象外です。プレイヤー側の設定で低遅延をオフにすれば動きます。

**バッジが表示されない**
既定ではオフになっています。「全サイト共通」パネルでオンにしてください。サイトのコントロールバーが見つからない場合は、プレイヤー左上に小さな黒い帯として表示されます。

**Twitch の映像だけエラーで止まる・固まる（Slipstream Live とは無関係の場合）**
Slipstream Live は再生「速度」を調整するだけの拡張機能なので、映像が完全に止まったり「エラー #〇〇〇〇」のようなコードが出たりするのは、たいてい Twitch や Chrome 自体の問題です。次を上から順に試してください。

1. [status.twitch.com](https://status.twitch.com/) で Twitch 側の障害情報を確認する
2. **シークレットウィンドウ**（`Ctrl+Shift+N` / Mac は `Cmd+Shift+N`）で同じ配信を開く
   → それで直るなら、原因は拡張機能かキャッシュです
3. 拡張機能、特に **広告ブロッカー** を一度すべてオフにする（Twitch は広告を映像そのものに埋め込んでいるため、広告ブロッカーがエラーの原因になっていることが非常に多いです）
4. `chrome://settings/help` から Chrome を最新版に更新する（公式サポートは最新 2 バージョンのみ）
5. `Ctrl+Shift+Delete`（Mac は `Cmd+Shift+Delete`）でキャッシュと Cookie を削除する

それでも直らない場合、特に画面が固まる・真っ黒になる場合は、`chrome://settings/system` の **「ハードウェア アクセラレーション」** を今と逆に切り替えて再起動してみてください。直らなければ元の設定に戻してください（常時オフにする設定ではありません）。

Twitch 公式の情報も参考にしてください。

1. 再生に関する問題のトラブルシューティング
[https://help.twitch.tv/s/article/playback-issue-troubleshooting?language=ja](https://help.twitch.tv/s/article/playback-issue-troubleshooting?language=ja)
2. 対応するブラウザ
[https://help.twitch.tv/s/article/supported-browsers?language=ja](https://help.twitch.tv/s/article/supported-browsers?language=ja)
3. ビデオ再生の問題を報告する方法
[https://help.twitch.tv/s/article/how-to-file-a-video-playback-issue?language=ja](https://help.twitch.tv/s/article/how-to-file-a-video-playback-issue?language=ja)
4. Twitch Status（公式システム稼働状況）
[https://status.twitch.com/](https://status.twitch.com/)

## 🔒 プライバシー

Slipstream Live は**外部との通信を一切行いません**。要求する権限は次の 2 つだけです。

* `storage` — 設定を端末に保存するため。
* `activeTab` — ポップアップを開いたとき、対応サイトかどうかを判定して適切なタブを選ぶため。

解析・テレメトリ・識別子・広告は一切ありません。詳しくは [PRIVACY.md](PRIVACY.md) を見てください。

## 👩💻 開発者向け

### ファイル構成

```
manifest.json          拡張機能マニフェスト（MV3）
popup.html/.css/.js    設定画面（オプションページも兼用）
common.js              storage / i18n API のラッパー
content.js             ISOLATED world: 設定を <html data-slpstrm="..."> へ書き出す
inject.js              MAIN world: 制御ループ本体（バッファ→モード→速度・音量）
adapters/              サイト別の橋渡し: youtube.js / twitch.js / twitcasting.js
shared/schema.js       設定の唯一の定義元（型・範囲・既定値）
shared/util.js         時系列窓・統計・DOM の小さなヘルパー
_locales/              9 言語分の UI 翻訳
docs/                  GitHub Pages: トップページ・プライバシーポリシー・取扱説明書（英日）と images/
```

MAIN world のスクリプトからは `chrome.storage` を触れないため、設定は `data-` 属性上の JSON 文字列として world 境界を越えます。
ページ側のスクリプトがこの属性を改ざんできてしまうので、`inject.js` は読み込んだ値を独自の基準で必ず再検証します。

### サイトを追加するには

`video()` / `media()` / `status()` / `needs()` / `root()` / `host()` / `reset()` と、`respectUserRate` / `gap` / `badgeClass` / `badgeStyle` を備えたアダプタを 1 つ書いて登録し、`shared/schema.js` の `SITES` と `manifest.json` に対応する項目を追加すれば完了です。`inject.js` 側の変更は不要です。

なおコンテンツスクリプトは全フレームへ注入されるため（`all_frames: true`）、1 つのページで複数のインスタンスが独立して起動します。
`<video>` を持たないフレームは 5 秒の猶予後にタイマーを停止するので、メインフレームが正常に動作していてもデバッグログには `timer stopped` が頻繁に現れます。

### デバッグ

ページのコンソール（拡張機能のコンソールではありません）で次を実行します。

```js
window.__slipstreamliveDebug = true;
```

1 秒ごとに、現在のモード・実再生速度・バッファ残量・短期統計・谷の統計・`room` の計算式・近道の基準値 `ample`・超過消費の累積 `drift`・定常判定 `calm` が出力されます。
バッファ関連の数値が `----` になっている場合は `health` が `NaN` であることを意味し、多くは `video.buffered` が空であることが原因です。
`calm=NO` が続く場合は定常でないと判定されており、谷の履歴が貯まらないため `room` も `----` になります。ただし残量が `ample` を超えている間は、その状態でも加速します。

また、ブラウザの言語設定を変えずに各言語の表示を確認したい場合は、設定画面を `popup.html?locale=de` のようにクエリ付きで開けます。
